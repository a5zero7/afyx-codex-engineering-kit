# Odoo reference schema for Phase 2B

Version references should remain concise, delta-first, and evidence-backed. When applicable, organize additions under:

- Status / runtime baseline
- Delta from previous major
- ORM / Python / models
- Views / XML / security
- Frontend / JavaScript / assets
- Reports / QWeb
- Manifest / loading
- High-risk version traps
- Validation
- Evidence with exact branch, file/symbol, or documentation section

Use precise classifications such as documented, present in source, deprecated, or removed; do not conflate deprecation with removal. Do not add empty sections or speculative claims. Claims must come from official Odoo documentation/source, official release or migration information, or target-repository evidence. Community material may help discovery but is not the compatibility source of truth.
